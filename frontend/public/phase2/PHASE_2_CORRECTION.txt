CORRECTION 1 — Strict Whitelist Revenue Eligibility
---------------------------------------------------
File: backend/services/financial_source_of_truth.py

Before:
    _is_revenue_eligible_invoice() returned True for any invoice whose
    status was not in EXCLUDED or INFORMATIONAL sets. Legacy/unknown
    statuses could be silently counted as revenue.

After:
    _is_revenue_eligible_invoice() is a STRICT whitelist:
        return (not proforma) AND (normalized_status in REVENUE_ELIGIBLE_INVOICE_STATUSES)

    Unknown / legacy statuses:
      - contribute 0 to net_invoiced_value
      - contribute 0 to outstanding_amount
      - trigger a new UNRECOGNIZED_INVOICE_STATUS warning
      - are labelled payment_status = "n/a_unknown"

    Draft invoices:
      - contribute 0 to net_invoiced_value
      - contribute 0 to outstanding_amount
      - are labelled payment_status = "n/a_draft"

    If a non-eligible invoice has active payments or credit notes,
    a NON_ELIGIBLE_INVOICE_HAS_ACTIVITY warning is emitted (records
    are preserved — the service never writes).

    New helper: _normalized_status(inv)  (lowercase, whitespace-safe).
    New constant: KNOWN_INVOICE_STATUSES = REVENUE_ELIGIBLE ∪ EXCLUDED ∪ INFORMATIONAL.
