FINANCIAL LOGIC CHANGES
-----------------------
NONE. Invoice calculations, proforma conversion, payment calc,
session values, credit notes, revenue and P&L are unmodified.
The Phase 1 endpoints are strictly GET-only and never write to
payments, invoices, ledger or any other collection.

DATABASE CHANGES
----------------
Only additive indexes, created by add_payment_history_indexes.py:
  payments: payment_date_created_desc, payment_amount,
            payment_method, payment_type, payment_status,
            payment_invoice_id, payment_receipt_number,
            payment_reference_number
  invoices: invoice_number_idx, invoice_company_name_idx,
            invoice_bill_to_name_idx
Schema is unchanged. Existing data is untouched.

API CONTRACT (new endpoints)
----------------------------
GET /api/finance/payments/history
    Query params: q, date_from, date_to, payment_method,
                  funding_source, status (active|reversed|all),
                  sort (newest|oldest|highest|lowest),
                  page (default 1), page_size (default 25, max 100)
    Response: { items, page, page_size, total, total_pages,
                sort, filters }

GET /api/finance/payments/history/export
    Same filters. Returns text/csv (hard cap 5000 rows).

GET /api/finance/payments/{payment_id}/detail
    Returns { payment, invoice, session, program, recorded_by_name }.

AUTHORIZATION
-------------
All three endpoints require role in
{admin, super_admin, finance}. Non-finance roles receive 403;
missing token receives 401. Verified by pytest.
