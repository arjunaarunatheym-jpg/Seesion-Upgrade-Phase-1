# 4. SUPERADMIN GOD MODE AUTHORITY MATRIX
################################################################################

    OPERATION                     PATH                                     STATUSES ALLOWED
    Correct invoice number        POST .../correct-number                  ALL (unique-checked)
    Preview value correction      POST .../correct-value/preview           ALL
    Execute value correction      POST .../correct-value (confirm=true)    ALL
    Correct invoice date          POST .../correct-date                    ALL
    Correct text/bill-to          POST .../correct-text                    ALL (money rejected)
    Correct issued CN             POST .../credit-notes/{id}/correct-issued issued only

    Every action requires:
        role == "super_admin"
        reason >= 5 chars
        idempotent by design
        audit row in superadmin_god_mode_audit with:
            entity_type, entity_id, action, reason,
            before_value, after_value,
            performed_by / performed_by_name / performed_by_email,
            performed_at, correction_type (for value corrections),
            preview (for value + issued-CN corrections).


################################################################################
# 5–9. CORRECTION DESIGNS (compact)
################################################################################

INVOICE NUMBER   — unique constraint pre-check, denormalized copies on
                   payments & credit_notes updated to the new number,
                   invoice UUID preserved, audit written.

INVOICE VALUE    — preview endpoint reuses Phase 2 SoT internal helper
                   (`_compute_invoice_snapshot`) to compute an "after"
                   snapshot WITHOUT mutating. Execute endpoint recalculates
                   subtotal & tax from tax_rate, re-derives canonical status
                   (issued vs partially_paid vs paid) from fresh SoT snapshot.
                   correction_type must be one of:
                       data_entry_correction | commercial_adjustment
                       | exceptional_override

INVOICE DATE     — invoice_date changed; created_at preserved intact.

BILL-TO / TEXT   — allowed set:
                     company_name, bill_to_name, bill_to_address,
                     bill_to_email, programme_name, session_name,
                     description, po_number, line_items_text_note.
                   Any monetary field in body → 400 MONEY_FIELDS_NOT_ALLOWED.

ISSUED CN        — allowed set: cn_number, cn_date, amount, reason,
                   description. On amount change, existing linked
                   journal entries are voided (idempotent) and a new
                   journal is re-posted via post_credit_note_issued
                   under the SuperAdmin correction audit.


################################################################################
# 10–13. NORMAL LOCK / SESSION / RESERVATION / CN DESIGN
################################################################################

CN normal locks:
    draft   → editable
    approved→ materially locked
    issued  → LOCKED (SuperAdmin correction only)
    voided  → LOCKED historical

Session-costing protection:
    finance_session.save_session_invoice() only mutates a PRE-ISSUE
    invoice. Issued/paid/terminal invoices raise INVOICE_LOCKED.

Session edit cascade:
    Only PRE_ISSUE invoices receive session cascades. Issued/paid
    invoices remain untouched.


################################################################################
# 14–17. ARCHIVE + DESTRUCTIVE-OP SAFEGUARDS + CONCURRENCY
################################################################################

- POST /api/sessions/{id}/archive preserves ALL financial records.
- DELETE /api/sessions/{id} in production rejects when financial history
  exists (SESSION_HAS_FINANCIAL_HISTORY, 409).
- DELETE /api/sessions/bulk/delete-all in production returns 403
  DESTRUCTIVE_OPERATION_DISABLED_IN_PRODUCTION.
- delete_invoice() never wipes CNs on invoices with financial history.
- Proforma-conversion concurrency: partial unique index
  uniq_converted_from_proforma_id_partial on invoices; combined with the
  pre-check in convert_proforma_to_invoice + race-safe re-check on insert
  failure, guarantees exactly ONE resulting invoice per proforma.
